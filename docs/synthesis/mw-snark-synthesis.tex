\begin{abstract}
SNARK supports answer extraction from refutation proofs, a mechanism that
connects automated theorem proving with deductive program synthesis.  This note
documents a small extension of the local SNARK example suite under
\texttt{examples/synthesis}.  The extension recasts classical
Manna--Waldinger developments as runnable SNARK examples: synthesis of the
unification algorithm, emergence of the binary-search paradigm in the
square-root approximation problem, subtractive greatest-common-divisor
computation, and quotient/remainder computation by recursive subtraction.  The
development also adds three further stress tests: stable merge, stable
partition, and a Boyer--Moore-style simplifier for normal-form IF-expressions
\cite{BoyerMoore1979}.  A separate MST development treats the classical
Kruskal, Jarnik--Prim, and Boruvka algorithms
\cite{Kruskal1956,Jarnik1930,Prim1957,Boruvka1926} as logical refinements of
a shared safe-extension skeleton.  It is not a verbatim
reproduction of the original deductive-tableau proofs.  Instead, it isolates
the central constructive obligations and uses SNARK's conditional answers to
extract program terms from proofs.  It also includes executable Lisp
interpretations of the extracted terms, making explicit the gap between a proof
answer and a runnable program.

\keywords{SNARK \and Answer extraction \and Deductive synthesis \and
Unification \and Binary search \and Greatest common divisor \and Integer
division}
\end{abstract}

\section{Overview}

Deductive program synthesis treats program construction as theorem proving.
The desired program is specified by an existential theorem: for each admissible
input there exists an output satisfying the specification.  A constructive
proof of that theorem carries enough information to compute the output.  In
SNARK, this information is represented by answers attached to rows.  When a
proof closes, \texttt{(answer t)} can be read as the extracted witness term.

The local development adds a Manna--Waldinger synthesis example file.  It
contributes seven entry points:
\begin{lstlisting}
(mw-unification-variable-case)
(mw-unification-constant-case)
(mw-unification-compound-case)
(mw-square-root-binary-search-step)
(mw-square-root-binary-search-program)
(mw-gcd-subtractive-program)
(mw-quotient-remainder-program)
\end{lstlisting}
The aggregator \texttt{(mw-synthesis-examples)} runs all seven and returns their
extracted program terms.  The examples are also wired into
\texttt{snark-system.lisp} and \texttt{snark-examples.asd}, so rebuilding SNARK
compiles them with the rest of the example suite.

The same file also contains runnable interpretations:
\begin{lstlisting}
(mw-run-unify term1 term2)
(mw-run-sqrt r eps)
(mw-run-gcd a b)
(mw-run-quotient-remainder n d)
(mw-executable-synthesis-demos)
\end{lstlisting}
These are ordinary Common Lisp functions.  They are included to show where the
SNARK answer term stops and concrete execution begins.

A second file, \texttt{new-synthesis-examples.lisp}, adds examples that are not
claimed as historical Manna--Waldinger reconstructions but that exercise the
same answer-extraction interface:
\begin{lstlisting}
(new-stable-merge-program)
(new-stable-partition-program)
(new-if-normal-form-simplifier-program)
(new-synthesis-examples)
\end{lstlisting}
It also includes executable interpretations:
\begin{lstlisting}
(new-executable-synthesis-demos)
\end{lstlisting}

A third file, \texttt{new-mst-synthesis.lisp}, develops minimum-spanning-tree
algorithms as a refinement hierarchy:
\begin{lstlisting}
(new-mst-synthesis-examples)
(new-run-mst graph :strategy :kruskal)
(new-run-mst graph :strategy :prim)
(new-run-mst graph :strategy :boruvka)
(new-run-mst-demo)
\end{lstlisting}

\section{Answer Extraction in the Development}

Each example follows the same pattern.  First, it initializes SNARK with
resolution and conditional answer creation:
\begin{lstlisting}
(initialize)
(use-resolution t)
(use-conditional-answer-creation t)
\end{lstlisting}
Next, it declares an abstract object language of constructors, predicates, and
program symbols.  The specification cases are asserted as implications.  The
goal is then proved with an answer template:
\begin{lstlisting}
(prove '(some-output-relation input ?result)
       :answer '(values ?result))
\end{lstlisting}
If two proof branches contribute different answers, SNARK combines them with
\texttt{ANSWER-IF}.  This is the key mechanism used here to expose conditional
branches in the synthesized program.

\section{Specification-to-Answer Catalogue}

This section records the complete middle layer for the examples: the informal
mathematical/logical specification, the actual SNARK input formulas, and the
answer extracted by SNARK.  Declarations of constructors and predicates are in
the source files; the listings here show the formulas sent to the prover and
the witness query.

\subsection{MW Unification: Variable Case}

Mathematically, the variable case is the occurs-check split:
\[
  \mathrm{occurs}(\mathrm{var}(v),t) \Rightarrow r=\mathrm{none},
  \qquad
  \neg\mathrm{occurs}(\mathrm{var}(v),t)
    \Rightarrow r=\mathrm{some}(\mathrm{bind}(v,t)).
\]
SNARK input:
\begin{lstlisting}
(assert '(implies (mw-occurs (mw-var v) term)
                  (mw-unify-out (mw-var v) term mw-none))
        :name 'mw-occurs-check-failure)
(assert '(implies (not (mw-occurs (mw-var v) term))
                  (mw-unify-out (mw-var v) term
                                (mw-some (mw-bind v term))))
        :name 'mw-variable-binding)
(prove '(mw-unify-out (mw-var v) term ?result)
       :answer '(values ?result))
\end{lstlisting}
Answer:
\begin{lstlisting}
(ANSWER-IF (MW-OCCURS (MW-VAR V) TERM)
  (VALUES MW-NONE)
  (VALUES (MW-SOME (MW-BIND V TERM))))
\end{lstlisting}

\subsection{MW Unification: Constant Case}

For constants, unification succeeds with the identity substitution exactly when
the symbols match:
\[
  \mathrm{same}(c,d) \Rightarrow r=\mathrm{some}(\mathrm{id}),
  \qquad
  \neg\mathrm{same}(c,d) \Rightarrow r=\mathrm{none}.
\]
SNARK input:
\begin{lstlisting}
(assert '(implies (mw-same-symbol c d)
                  (mw-unify-out (mw-const c) (mw-const d)
                                (mw-some mw-id)))
        :name 'mw-identical-constants)
(assert '(implies (not (mw-same-symbol c d))
                  (mw-unify-out (mw-const c) (mw-const d) mw-none))
        :name 'mw-distinct-constants)
(prove '(mw-unify-out (mw-const c) (mw-const d) ?result)
       :answer '(values ?result))
\end{lstlisting}
Answer:
\begin{lstlisting}
(ANSWER-IF (MW-SAME-SYMBOL C D)
  (VALUES (MW-SOME MW-ID))
  (VALUES MW-NONE))
\end{lstlisting}

\subsection{MW Unification: Compound Case}

For compound terms, first unify the heads.  If that fails, fail.  Otherwise
substitute the first unifier through the tails, unify the tails, and compose
the two substitutions if the second unification succeeds.
SNARK input:
\begin{lstlisting}
(assert '(implies
          (mw-fail (mw-unify m m1))
          (mw-unify-out (mw-app m n) (mw-app m1 n1) mw-none))
        :name 'mw-compound-first-fails)
(assert '(implies
          (and (not (mw-fail (mw-unify m m1)))
               (mw-fail
                (mw-unify
                 (mw-subst (mw-subst-of (mw-unify m m1)) n)
                 (mw-subst (mw-subst-of (mw-unify m m1)) n1))))
          (mw-unify-out (mw-app m n) (mw-app m1 n1) mw-none))
        :name 'mw-compound-second-fails)
(assert '(implies
          (and (not (mw-fail (mw-unify m m1)))
               (not
                (mw-fail
                 (mw-unify
                  (mw-subst (mw-subst-of (mw-unify m m1)) n)
                  (mw-subst (mw-subst-of (mw-unify m m1)) n1)))))
          (mw-unify-out
           (mw-app m n)
           (mw-app m1 n1)
           (mw-some
            (mw-compose
             (mw-subst-of (mw-unify m m1))
             (mw-subst-of
              (mw-unify
               (mw-subst (mw-subst-of (mw-unify m m1)) n)
               (mw-subst (mw-subst-of (mw-unify m m1)) n1)))))))
        :name 'mw-compound-compose)
(prove '(mw-unify-out (mw-app m n) (mw-app m1 n1) ?result)
       :answer '(values ?result))
\end{lstlisting}
Answer:
\begin{lstlisting}
(ANSWER-IF (MW-FAIL (MW-UNIFY M M1))
  (VALUES MW-NONE)
  (ANSWER-IF
    (MW-FAIL
      (MW-UNIFY
        (MW-SUBST (MW-SUBST-OF (MW-UNIFY M M1)) N)
        (MW-SUBST (MW-SUBST-OF (MW-UNIFY M M1)) N1)))
    (VALUES MW-NONE)
    (VALUES
      (MW-SOME
        (MW-COMPOSE
          (MW-SUBST-OF (MW-UNIFY M M1))
          (MW-SUBST-OF
            (MW-UNIFY
              (MW-SUBST (MW-SUBST-OF (MW-UNIFY M M1)) N)
              (MW-SUBST (MW-SUBST-OF (MW-UNIFY M M1)) N1))))))))
\end{lstlisting}

\subsection{MW Square Root: Binary-Search Step}

For a current lower endpoint \(z\), choose the right half exactly when
\((z+\epsilon)^2\leq r\):
\[
  (z+\epsilon)^2\leq r \Rightarrow a=z+\epsilon,
  \qquad
  \neg((z+\epsilon)^2\leq r) \Rightarrow a=z.
\]
SNARK input:
\begin{lstlisting}
(assert '(implies
          (mw-le (mw-square (mw-plus z eps)) r)
          (mw-sqrt-within r (mw-plus z eps) eps))
        :name 'mw-square-root-right-half)
(assert '(implies
          (not (mw-le (mw-square (mw-plus z eps)) r))
          (mw-sqrt-within r z eps))
        :name 'mw-square-root-left-half)
(prove '(mw-sqrt-within r ?answer eps)
       :answer '(values ?answer))
\end{lstlisting}
Answer:
\begin{lstlisting}
(ANSWER-IF (MW-LE (MW-SQUARE (MW-PLUS Z EPS)) R)
  (VALUES (MW-PLUS Z EPS))
  (VALUES Z))
\end{lstlisting}

\subsection{MW Square Root: Recursive Program}

The recursive skeleton returns zero at a large tolerance; otherwise it recurses
at doubled tolerance and applies the same right-half test:
\[
  \mathrm{large}(r,\epsilon) \Rightarrow a=0,
  \quad
  \neg\mathrm{large}(r,\epsilon) \Rightarrow
  a \in \{s,\;s+\epsilon\}
\]
where \(s=\mathrm{sqrt}(r,2\epsilon)\), choosing \(s+\epsilon\) exactly when
\((s+\epsilon)^2\leq r\).  SNARK input:
\begin{lstlisting}
(assert '(implies
          (mw-large-tolerance r eps)
          (mw-sqrt-within r zero eps))
        :name 'mw-square-root-base-case)
(assert '(implies
          (and (not (mw-large-tolerance r eps))
               (mw-le
                (mw-square
                 (mw-plus (mw-sqrt r (mw-double eps)) eps))
                r))
          (mw-sqrt-within
           r
           (mw-plus (mw-sqrt r (mw-double eps)) eps)
           eps))
        :name 'mw-square-root-recursive-right-half)
(assert '(implies
          (and (not (mw-large-tolerance r eps))
               (not
                (mw-le
                 (mw-square
                  (mw-plus (mw-sqrt r (mw-double eps)) eps))
                 r)))
          (mw-sqrt-within r (mw-sqrt r (mw-double eps)) eps))
        :name 'mw-square-root-recursive-left-half)
(prove '(mw-sqrt-within r ?answer eps)
       :answer '(values ?answer))
\end{lstlisting}
Answer:
\begin{lstlisting}
(ANSWER-IF (MW-LARGE-TOLERANCE R EPS)
  (VALUES ZERO)
  (ANSWER-IF
    (MW-LE
      (MW-SQUARE
        (MW-PLUS (MW-SQRT R (MW-DOUBLE EPS)) EPS))
      R)
    (VALUES (MW-PLUS (MW-SQRT R (MW-DOUBLE EPS)) EPS))
    (VALUES (MW-SQRT R (MW-DOUBLE EPS)))))
\end{lstlisting}

\subsection{MW Greatest Common Divisor}

For positive integers, the subtractive Euclidean split is:
\[
  a=b \Rightarrow g=a,\quad
  a>b \Rightarrow g=\mathrm{gcd}(a-b,b),\quad
  b>a \Rightarrow g=\mathrm{gcd}(a,b-a).
\]
SNARK input:
\begin{lstlisting}
(assert '(or (mw-eq a b) (mw-gt a b) (mw-gt b a))
        :name 'mw-gcd-trichotomy)
(assert '(implies
          (mw-eq a b)
          (mw-gcd-out a b a))
        :name 'mw-gcd-equal-case)
(assert '(implies
          (mw-gt a b)
          (mw-gcd-out a b (mw-gcd (mw-minus a b) b)))
        :name 'mw-gcd-left-reduction)
(assert '(implies
          (mw-gt b a)
          (mw-gcd-out a b (mw-gcd a (mw-minus b a))))
        :name 'mw-gcd-right-reduction)
(prove '(mw-gcd-out a b ?answer)
       :answer '(values ?answer))
\end{lstlisting}
Answer:
\begin{lstlisting}
(ANSWER-IF (MW-GT B A)
  (VALUES (MW-GCD A (MW-MINUS B A)))
  (ANSWER-IF (MW-GT A B)
    (VALUES (MW-GCD (MW-MINUS A B) B))
    (VALUES A)))
\end{lstlisting}

\subsection{MW Quotient and Remainder}

For natural \(n\) and positive \(d\), return \(q,r\) with
\(n=qd+r\) and \(0\leq r<d\).  The recursive split is:
\[
  n<d \Rightarrow (q,r)=(0,n),\quad
  n\geq d \Rightarrow
  (q,r)=(1+q',r')
\]
where \((q',r')=\mathrm{qr}(n-d,d)\).  SNARK input:
\begin{lstlisting}
(assert '(implies
          (mw-lt n d)
          (mw-qr-out n d (mw-pair zero n)))
        :name 'mw-qr-base-case)
(assert '(implies
          (not (mw-lt n d))
          (mw-qr-out
           n
           d
           (mw-pair
            (mw-succ (mw-quotient-of (mw-qr (mw-minus n d) d)))
            (mw-remainder-of (mw-qr (mw-minus n d) d)))))
        :name 'mw-qr-recursive-case)
(prove '(mw-qr-out n d ?answer)
       :answer '(values ?answer))
\end{lstlisting}
Answer:
\begin{lstlisting}
(ANSWER-IF (MW-LT N D)
  (VALUES (MW-PAIR ZERO N))
  (VALUES
    (MW-PAIR
      (MW-SUCC (MW-QUOTIENT-OF (MW-QR (MW-MINUS N D) D)))
      (MW-REMAINDER-OF (MW-QR (MW-MINUS N D) D)))))
\end{lstlisting}

\subsection{New Stable Merge}

For nonempty sorted lists \(x::xs\) and \(y::ys\), stability chooses the left
head on equality:
\[
  x\leq y \Rightarrow m=x::\mathrm{merge}(xs,y::ys),\quad
  \neg(x\leq y) \Rightarrow m=y::\mathrm{merge}(x::xs,ys).
\]
SNARK input:
\begin{lstlisting}
(assert '(implies
          (new-le x y)
          (new-merge-out
           (new-cons x xs)
           (new-cons y ys)
           (new-cons x (new-merge xs (new-cons y ys)))))
        :name 'new-merge-take-left)
(assert '(implies
          (not (new-le x y))
          (new-merge-out
           (new-cons x xs)
           (new-cons y ys)
           (new-cons y (new-merge (new-cons x xs) ys))))
        :name 'new-merge-take-right)
(prove '(new-merge-out (new-cons x xs) (new-cons y ys) ?answer)
       :answer '(values ?answer))
\end{lstlisting}
Answer:
\begin{lstlisting}
(ANSWER-IF (NEW-LE X Y)
  (VALUES (NEW-CONS X (NEW-MERGE XS (NEW-CONS Y YS))))
  (VALUES (NEW-CONS Y (NEW-MERGE (NEW-CONS X XS) YS))))
\end{lstlisting}

\subsection{New Stable Partition}

For \(x::xs\), recursively partition the tail and put \(x\) in the first or
second component depending on the predicate:
\[
  P(x) \Rightarrow (k,d)=(x::k',d'),\quad
  \neg P(x) \Rightarrow (k,d)=(k',x::d')
\]
where \((k',d')=\mathrm{partition}(xs)\).  SNARK input:
\begin{lstlisting}
(assert '(implies
          (new-keeps x)
          (new-partition-out
           (new-cons x xs)
           (new-pair
            (new-cons x (new-left (new-partition xs)))
            (new-right (new-partition xs)))))
        :name 'new-partition-keep)
(assert '(implies
          (not (new-keeps x))
          (new-partition-out
           (new-cons x xs)
           (new-pair
            (new-left (new-partition xs))
            (new-cons x (new-right (new-partition xs))))))
        :name 'new-partition-drop)
(prove '(new-partition-out (new-cons x xs) ?answer)
       :answer '(values ?answer))
\end{lstlisting}
Answer:
\begin{lstlisting}
(ANSWER-IF (NEW-KEEPS X)
  (VALUES
    (NEW-PAIR
      (NEW-CONS X (NEW-LEFT (NEW-PARTITION XS)))
      (NEW-RIGHT (NEW-PARTITION XS))))
  (VALUES
    (NEW-PAIR
      (NEW-LEFT (NEW-PARTITION XS))
      (NEW-CONS X (NEW-RIGHT (NEW-PARTITION XS))))))
\end{lstlisting}

\subsection{New IF-Expression Simplifier}

Boyer and Moore use IF-expressions as a central datatype in the tautology
checker development of \emph{A Computational Logic} \cite{BoyerMoore1979}.
Here an expression is either \(\mathsf{True}\), \(\mathsf{False}\), a variable,
or \(\mathsf{IF}(x,t,e)\).  The normal-form invariant says that every IF
condition is a variable and that there are no immediate redundancies of the
form \(\mathsf{IF}(x,A,A)\).  The stronger simplifier carries a path
environment \(\Gamma\) so that no variable is repeated along any branch.  Let
\[
  T_x=S(t,\Gamma[x:=\mathsf{true}]),
  \qquad
  E_x=S(e,\Gamma[x:=\mathsf{false}]).
\]
Then the recursive IF-node cases are:
\begin{align*}
  \Gamma(x)=\mathsf{true}
    &\Rightarrow S(\mathsf{IF}(x,t,e),\Gamma)=S(t,\Gamma),\\
  \Gamma(x)=\mathsf{false}
    &\Rightarrow S(\mathsf{IF}(x,t,e),\Gamma)=S(e,\Gamma),\\
  x\notin\Gamma,\; T_x=E_x
    &\Rightarrow S(\mathsf{IF}(x,t,e),\Gamma)=T_x,\\
  x\notin\Gamma,\; T_x\neq E_x
    &\Rightarrow S(\mathsf{IF}(x,t,e),\Gamma)=\mathsf{IF}(x,T_x,E_x).
\end{align*}
The executable interpretation also handles the leaf cases:
\(\mathsf{True}\) and \(\mathsf{False}\) return themselves; a variable already
fixed by \(\Gamma\) becomes the corresponding truth value; an unknown variable
returns itself.  The SNARK proof below isolates the recursive IF-node case.
SNARK input:
\begin{lstlisting}
(assert '(new-if-expr expr)
        :name 'new-if-input-is-if-node)
(assert '(not (and (new-assumed-true (new-condition expr) env)
                   (new-assumed-false (new-condition expr) env)))
        :name 'new-if-assumptions-consistent)
(assert '(implies
          (and (new-if-expr expr)
               (new-assumed-true (new-condition expr) env))
          (new-if-simplify-out
           expr
           env
           (new-simplify-if (new-then-branch expr) env)))
        :name 'new-if-condition-known-true)
(assert '(implies
          (and (new-if-expr expr)
               (not (new-assumed-true (new-condition expr) env))
               (new-assumed-false (new-condition expr) env))
          (new-if-simplify-out
           expr
           env
           (new-simplify-if (new-else-branch expr) env)))
        :name 'new-if-condition-known-false)
(assert '(implies
          (and (new-if-expr expr)
               (not (new-assumed-true (new-condition expr) env))
               (not (new-assumed-false (new-condition expr) env))
               (new-same
                (new-simplify-if
                 (new-then-branch expr)
                 (new-extend-true (new-condition expr) env))
                (new-simplify-if
                 (new-else-branch expr)
                 (new-extend-false (new-condition expr) env))))
          (new-if-simplify-out
           expr
           env
           (new-simplify-if
            (new-then-branch expr)
            (new-extend-true (new-condition expr) env))))
        :name 'new-if-redundant-branches)
(assert '(implies
          (and (new-if-expr expr)
               (not (new-assumed-true (new-condition expr) env))
               (not (new-assumed-false (new-condition expr) env))
               (not
                (new-same
                 (new-simplify-if
                  (new-then-branch expr)
                  (new-extend-true (new-condition expr) env))
                 (new-simplify-if
                  (new-else-branch expr)
                  (new-extend-false (new-condition expr) env)))))
          (new-if-simplify-out
           expr
           env
           (new-if
            (new-condition expr)
            (new-simplify-if
             (new-then-branch expr)
             (new-extend-true (new-condition expr) env))
            (new-simplify-if
             (new-else-branch expr)
             (new-extend-false (new-condition expr) env)))))
        :name 'new-if-rebuild)
(prove '(new-if-simplify-out expr env ?answer)
       :answer '(values ?answer))
\end{lstlisting}
Answer:
\begin{lstlisting}
(ANSWER-IF (NEW-ASSUMED-FALSE (NEW-CONDITION EXPR) ENV)
  (VALUES (NEW-SIMPLIFY-IF (NEW-ELSE-BRANCH EXPR) ENV))
  (ANSWER-IF (NEW-ASSUMED-TRUE (NEW-CONDITION EXPR) ENV)
    (VALUES (NEW-SIMPLIFY-IF (NEW-THEN-BRANCH EXPR) ENV))
    (ANSWER-IF
      (NEW-SAME
        (NEW-SIMPLIFY-IF
          (NEW-THEN-BRANCH EXPR)
          (NEW-EXTEND-TRUE (NEW-CONDITION EXPR) ENV))
        (NEW-SIMPLIFY-IF
          (NEW-ELSE-BRANCH EXPR)
          (NEW-EXTEND-FALSE (NEW-CONDITION EXPR) ENV)))
      (VALUES
        (NEW-SIMPLIFY-IF
          (NEW-THEN-BRANCH EXPR)
          (NEW-EXTEND-TRUE (NEW-CONDITION EXPR) ENV)))
      (VALUES
        (NEW-IF
          (NEW-CONDITION EXPR)
          (NEW-SIMPLIFY-IF
            (NEW-THEN-BRANCH EXPR)
            (NEW-EXTEND-TRUE (NEW-CONDITION EXPR) ENV))
          (NEW-SIMPLIFY-IF
            (NEW-ELSE-BRANCH EXPR)
            (NEW-EXTEND-FALSE (NEW-CONDITION EXPR) ENV)))))))
\end{lstlisting}

\subsection{New MST: Abstract Specification}

The MST development reifies sets, cuts, forests, batches, and strategies as
first-order objects.  The second-order comparison against every candidate tree
is represented by first-order predicates over tree objects, including
\texttt{NEW-SPANNING-TREE} and \texttt{NEW-MINIMUM-TOTAL-WEIGHT}.  At the top
level:
\[
  \mathrm{MST}(G,T) \equiv
  \mathrm{SpanningTree}(G,T)\land \mathrm{MinimumTotalWeight}(G,T).
\]
SNARK input:
\begin{lstlisting}
(assert '(new-spanning-tree g tree)
        :name 'new-mst-spanning-tree-premise)
(assert '(new-minimum-total-weight g tree)
        :name 'new-mst-minimality-premise)
(assert '(implies
          (and (new-spanning-tree g tree)
               (new-minimum-total-weight g tree))
          (new-mst-out g tree tree))
        :name 'new-mst-specification)
(prove '(new-mst-out g tree ?answer)
       :answer '(values ?answer))
\end{lstlisting}
Answer:
\begin{lstlisting}
(VALUES TREE)
\end{lstlisting}

\subsection{New MST: Abstract Greedy Skeleton}

The first algorithmic refinement is deliberately not Kruskal, Prim, or Boruvka.
It states only the shared greedy invariant:
\begin{align*}
  \mathrm{complete}(G,F) &\Rightarrow A=F,\\
  \neg\mathrm{complete}(G,F) &\Rightarrow
    A=\mathrm{Greedy}(G,\mathrm{Extend}(G,F)).
\end{align*}
SNARK input:
\begin{lstlisting}
(assert '(implies
          (new-mst-complete g forest)
          (new-mst-greedy-out g forest forest))
        :name 'new-mst-greedy-finished)
(assert '(implies
          (not (new-mst-complete g forest))
          (new-mst-greedy-out
           g
           forest
           (new-mst-greedy g (new-mst-extend g forest))))
        :name 'new-mst-greedy-continues)
(prove '(new-mst-greedy-out g forest ?answer)
       :answer '(values ?answer))
\end{lstlisting}
Answer:
\begin{lstlisting}
(ANSWER-IF (NEW-MST-COMPLETE G FOREST)
  (VALUES FOREST)
  (VALUES (NEW-MST-GREEDY G (NEW-MST-EXTEND G FOREST))))
\end{lstlisting}

\subsection{New MST: Safe Extension}

The next refinement exposes the safe-extension point.  A Boruvka-style batch of
safe edges may be added at once; otherwise the refinement adds one safe edge:
\[
  \mathrm{SafeBatch}(G,F,B)\Rightarrow A=F+B,\qquad
  \mathrm{SafeEdge}(G,F,e)\Rightarrow A=F+e.
\]
SNARK input:
\begin{lstlisting}
(assert '(or (new-safe-batch g forest batch)
             (new-safe-edge g forest edge))
        :name 'new-mst-extension-kind)
(assert '(implies
          (new-safe-batch g forest batch)
          (new-mst-extension-out
           g
           forest
           (new-mst-add-batch batch forest)))
        :name 'new-mst-safe-batch-extension)
(assert '(implies
          (and (not (new-safe-batch g forest batch))
               (new-safe-edge g forest edge))
          (new-mst-extension-out
           g
           forest
           (new-mst-add-edge edge forest)))
        :name 'new-mst-safe-edge-extension)
(prove '(new-mst-extension-out g forest ?answer)
       :answer '(values ?answer))
\end{lstlisting}
Answer:
\begin{lstlisting}
(ANSWER-IF (NEW-SAFE-EDGE G FOREST EDGE)
  (ANSWER-IF (NEW-SAFE-BATCH G FOREST BATCH)
    (VALUES (NEW-MST-ADD-BATCH BATCH FOREST))
    (VALUES (NEW-MST-ADD-EDGE EDGE FOREST)))
  (VALUES (NEW-MST-ADD-BATCH BATCH FOREST)))
\end{lstlisting}

\subsection{New MST: Cut Property}

The cut-property refinement says that a lightest edge crossing a cut respected
by the current forest is a safe single-edge extension:
\[
  \mathrm{RespectedCut}(G,F,C)\land
  \mathrm{Crosses}(e,C)\land
  \mathrm{LightestCrossing}(G,e,C)
  \Rightarrow A=F+e.
\]
SNARK input:
\begin{lstlisting}
(assert '(new-cut-respected g forest cut)
        :name 'new-mst-cut-respected-premise)
(assert '(new-crosses-cut edge cut)
        :name 'new-mst-cut-crossing-premise)
(assert '(new-lightest-crossing g edge cut)
        :name 'new-mst-cut-lightest-premise)
(assert '(implies
          (and (new-cut-respected g forest cut)
               (new-crosses-cut edge cut)
               (new-lightest-crossing g edge cut))
          (new-mst-extension-out
           g
           forest
           (new-mst-add-edge edge forest)))
        :name 'new-mst-cut-property-extension)
(prove '(new-mst-extension-out g forest ?answer)
       :answer '(values ?answer))
\end{lstlisting}
Answer:
\begin{lstlisting}
(VALUES (NEW-MST-ADD-EDGE EDGE FOREST))
\end{lstlisting}

\subsection{New MST: Kruskal, Prim, and Boruvka}

Kruskal, Prim/Jarnik, and Boruvka are encoded as specializations of the same
safe-extension relation:
\begin{align*}
  \mathrm{KruskalEligible}(G,F,e)\land\mathrm{KruskalLightest}(G,F,e)
    &\Rightarrow A=F+e,\\
  \mathrm{PrimFrontier}(G,F,r,e)\land\mathrm{PrimLightest}(G,F,r,e)
    &\Rightarrow A=F+e,\\
  \mathrm{BoruvkaBatch}(G,F,B)
    &\Rightarrow A=F+B.
\end{align*}
Representative SNARK input for the Kruskal refinement:
\begin{lstlisting}
(assert '(new-kruskal-eligible g forest edge)
        :name 'new-mst-kruskal-eligible-premise)
(assert '(new-kruskal-lightest g forest edge)
        :name 'new-mst-kruskal-lightest-premise)
(assert '(implies
          (and (new-kruskal-eligible g forest edge)
               (new-kruskal-lightest g forest edge))
          (new-mst-extension-out
           g
           forest
           (new-mst-add-edge edge forest)))
        :name 'new-mst-kruskal-extension)
(prove '(new-mst-extension-out g forest ?answer)
       :answer '(values ?answer))
\end{lstlisting}
The extracted answers for the three refinements are:
\begin{lstlisting}
(KRUSKAL-REFINEMENT
  (VALUES (NEW-MST-ADD-EDGE EDGE FOREST)))

(PRIM-REFINEMENT
  (VALUES (NEW-MST-ADD-EDGE EDGE FOREST)))

(BORUVKA-REFINEMENT
  (VALUES (NEW-MST-ADD-BATCH BATCH FOREST)))
\end{lstlisting}

\subsection{New MST: Strategy Dispatch and Executable Leaves}

The final symbolic layer dispatches among the concrete refinements:
\begin{lstlisting}
(assert '(or (new-strategy-kruskal strategy)
             (new-strategy-prim strategy)
             (new-strategy-boruvka strategy))
        :name 'new-mst-strategy-cases)
(prove '(new-mst-strategy-out g forest strategy ?answer)
       :answer '(values ?answer))
\end{lstlisting}
The resulting proof answer is a nested \texttt{ANSWER-IF} over the strategy
predicates.  SNARK does not simplify all impossible combinations away in the
answer term; the executable layer supplies the concrete dispatch:
\begin{lstlisting}
(new-run-mst graph :strategy :kruskal)
(new-run-mst graph :strategy :prim)
(new-run-mst graph :strategy :boruvka)
\end{lstlisting}
On the sample finite graph, all three concrete interpretations return total
weight \(9\), though the edge order and tie choices differ.

\section{Working Example I: Unification}

Manna and Waldinger's unification paper specifies unification as the task of
finding a substitution that makes two expressions identical, or reporting
failure when no such substitution exists \cite{MannaWaldinger1981}.  Later
presentations emphasize the same existential-output view and its fit with
SNARK-style proof search \cite{Waldinger2021}.  The local SNARK example uses a
small first-order term language:
\begin{lstlisting}
mw-var, mw-const, mw-app        ; expression constructors
mw-bind, mw-compose            ; substitution constructors
mw-unify, mw-subst, mw-subst-of
mw-none, mw-some               ; failure/success result constructors
\end{lstlisting}

\subsection{Variable Case}

The variable case encodes the occurs check:
\begin{align*}
  \mathrm{occurs}(\mathrm{var}(v),t)
    &\Rightarrow \mathrm{unify\_out}(\mathrm{var}(v),t,\mathrm{none}),\\
  \neg\mathrm{occurs}(\mathrm{var}(v),t)
    &\Rightarrow \mathrm{unify\_out}(\mathrm{var}(v),t,
       \mathrm{some}(\mathrm{bind}(v,t))).
\end{align*}
The query asks SNARK to find a result:
\begin{lstlisting}
(prove '(mw-unify-out (mw-var v) term ?result)
       :answer '(values ?result))
\end{lstlisting}
The extracted answer is:
\begin{lstlisting}
(ANSWER-IF (MW-OCCURS (MW-VAR V) TERM)
  (VALUES MW-NONE)
  (VALUES (MW-SOME (MW-BIND V TERM))))
\end{lstlisting}
This is the expected program fragment: fail if the occurs check fails;
otherwise return the singleton binding.

\subsection{Compound Case}

For compound terms, the classical algorithm recursively unifies the first
components, substitutes that result through the remaining components, then
unifies the remaining components and composes substitutions.  The SNARK
obligations encode three cases:
\begin{enumerate}
\item the first recursive unification fails;
\item the first succeeds but the second recursive unification fails;
\item both succeed and their substitutions are composed.
\end{enumerate}
The extracted answer is the following nested conditional:
\begin{lstlisting}
(ANSWER-IF (MW-FAIL (MW-UNIFY M M1))
  (VALUES MW-NONE)
  (ANSWER-IF
    (MW-FAIL
      (MW-UNIFY
        (MW-SUBST (MW-SUBST-OF (MW-UNIFY M M1)) N)
        (MW-SUBST (MW-SUBST-OF (MW-UNIFY M M1)) N1)))
    (VALUES MW-NONE)
    (VALUES
      (MW-SOME
        (MW-COMPOSE
          (MW-SUBST-OF (MW-UNIFY M M1))
          (MW-SUBST-OF
            (MW-UNIFY
              (MW-SUBST (MW-SUBST-OF (MW-UNIFY M M1)) N)
              (MW-SUBST (MW-SUBST-OF (MW-UNIFY M M1)) N1))))))))
\end{lstlisting}
This term mirrors the conventional recursive unification skeleton, while
remaining within SNARK's first-order answer-extraction mechanism.

\section{Working Example II: Square Root and Binary Search}

Manna and Waldinger's binary-search example starts from a specification for
approximating the square root of a nonnegative real number within a positive
tolerance.  Their derivation shows that a binary-search step emerges naturally:
given a rougher interval of width \(2\epsilon\), test whether the exact square
root is in the right half; if so, move the lower endpoint right by
\(\epsilon\), otherwise keep it \cite{MannaWaldinger1985IJCAI,MannaWaldinger1987}.
The local SNARK development abstracts away the full real
arithmetic theory and focuses on this constructive branch.

\subsection{Binary-Search Step}

The predicate \texttt{MW-SQRT-WITHIN} denotes that an answer is within the
desired interval.  The predicate \texttt{MW-LE} abstracts the comparison
\((z+\epsilon)^2 \leq r\).  The two obligations are:
\begin{align*}
  (z+\epsilon)^2 \leq r
    &\Rightarrow \mathrm{sqrt\_within}(r,z+\epsilon,\epsilon),\\
  \neg((z+\epsilon)^2 \leq r)
    &\Rightarrow \mathrm{sqrt\_within}(r,z,\epsilon).
\end{align*}
The extracted SNARK answer is:
\begin{lstlisting}
(ANSWER-IF (MW-LE (MW-SQUARE (MW-PLUS Z EPS)) R)
  (VALUES (MW-PLUS Z EPS))
  (VALUES Z))
\end{lstlisting}
This is the binary-search branch in its smallest form.

\subsection{Recursive Skeleton}

The second square-root example adds a base-case test and a recursive call
\texttt{MW-SQRT} at doubled
tolerance:
\begin{lstlisting}
(ANSWER-IF (MW-LARGE-TOLERANCE R EPS)
  (VALUES ZERO)
  (ANSWER-IF
    (MW-LE
      (MW-SQUARE
        (MW-PLUS (MW-SQRT R (MW-DOUBLE EPS)) EPS))
      R)
    (VALUES (MW-PLUS (MW-SQRT R (MW-DOUBLE EPS)) EPS))
    (VALUES (MW-SQRT R (MW-DOUBLE EPS)))))
\end{lstlisting}
This is faithful to the structural idea in the original derivation: use a
larger tolerance recursively to obtain a rough estimate, then decide which half
of the interval contains the desired value.

\section{Working Example III: Greatest Common Divisor}

Manna and Waldinger used the greatest-common-divisor program as one of their
arithmetic examples in the intermittent-assertion account of program
correctness \cite{MannaWaldinger1978}.  The local SNARK example reuses the same
subtractive Euclidean structure in synthesis form.  For positive integers
\(a\) and \(b\), one of three cases applies:
\begin{align*}
  a=b &\Rightarrow \mathrm{gcd}(a,b)=a,\\
  a>b &\Rightarrow \mathrm{gcd}(a,b)=\mathrm{gcd}(a-b,b),\\
  b>a &\Rightarrow \mathrm{gcd}(a,b)=\mathrm{gcd}(a,b-a).
\end{align*}
In SNARK, the comparison predicates and subtraction operation are kept
abstract.  The proof asks for an output satisfying \texttt{MW-GCD-OUT}:
\begin{lstlisting}
(prove '(mw-gcd-out a b ?answer)
       :answer '(values ?answer))
\end{lstlisting}
The extracted answer is:
\begin{lstlisting}
(ANSWER-IF (MW-GT B A)
  (VALUES (MW-GCD A (MW-MINUS B A)))
  (ANSWER-IF (MW-GT A B)
    (VALUES (MW-GCD (MW-MINUS A B) B))
    (VALUES A)))
\end{lstlisting}
The order of tests is chosen by SNARK's proof search, but the control
structure is the expected one: when neither strict inequality branch applies,
the equality case returns \(a\).

\section{Working Example IV: Quotient and Remainder}

The quotient/remainder example follows the integer-division development in
Manna and Waldinger's TOPLAS paper on deductive program synthesis
\cite{MannaWaldinger1980}.  The target computation is: for natural \(n\) and
positive \(d\), return \(q,r\) such that
\[
  n = qd + r \quad\hbox{and}\quad 0 \leq r < d.
\]
The constructive split is the familiar recursive-subtraction program.  If
\(n<d\), the quotient is zero and the remainder is \(n\).  Otherwise, recurse
on \(n-d\), increment the quotient component, and keep the recursive remainder.
The SNARK proof is:
\begin{lstlisting}
(prove '(mw-qr-out n d ?answer)
       :answer '(values ?answer))
\end{lstlisting}
and the extracted answer is:
\begin{lstlisting}
(ANSWER-IF (MW-LT N D)
  (VALUES (MW-PAIR ZERO N))
  (VALUES
    (MW-PAIR
      (MW-SUCC (MW-QUOTIENT-OF (MW-QR (MW-MINUS N D) D)))
      (MW-REMAINDER-OF (MW-QR (MW-MINUS N D) D)))))
\end{lstlisting}
Here again the proof term is not yet host-language code.  It names a recursive
call \texttt{MW-QR}, projections from its pair result, and arithmetic
operations that must be interpreted before the program can be run.

\section{Working Example V: MST Refinement Ladder}

The minimum-spanning-tree development is the most substantial new example in
the suite.  Unlike the small branch-extraction examples, it is organized as a
hierarchy of specifications and refinements.  The point is not to choose
Kruskal, Jarnik--Prim, or Boruvka
\cite{Kruskal1956,Jarnik1930,Prim1957,Boruvka1926} at the top.  Instead, the
development first states what an MST witness is, then introduces a generic
greedy extension operator, then refines that extension through the cut
property, and only at the leaves commits to the familiar algorithm families.

\subsection{Reifying the Specification}

The mathematical specification supplied by the user has the right high-level
shape:
\[
  \mathrm{MST}(G,T) \equiv
  \mathrm{SpanningTree}(G,T)\land
  \mathrm{MinimumWeight}(G,T).
\]
Here the minimum-weight clause abbreviates:
\[
  \mathrm{MinimumWeight}(G,T) \equiv
  \forall S.\,(\mathrm{SpanningTree}(G,S)\Rightarrow
  \mathrm{WeightLeq}(T,S)).
\]
To keep the SNARK development first-order, candidate trees, cuts, forests,
batches, and strategies are treated as first-order objects.  Thus the
second-order quantification over edge predicates is represented by predicates
over reified objects:
\begin{lstlisting}
NEW-SPANNING-TREE(G,T)
NEW-MINIMUM-TOTAL-WEIGHT(G,T)
NEW-CUT-RESPECTED(G,F,CUT)
NEW-SAFE-EDGE(G,F,E)
NEW-SAFE-BATCH(G,F,BATCH)
\end{lstlisting}
Reachability and weight comparison remain auxiliary predicates, just as in the
input specification.  This keeps the logical surface close to the mathematical
contract while making each refinement clause a first-order SNARK formula.

\subsection{The Abstract Greedy Program}

The first executable-looking answer is not any named MST algorithm.  It is the
shared greedy recurrence:
\[
  F\ \hbox{complete} \Rightarrow F,\qquad
  F\ \hbox{incomplete} \Rightarrow
  \mathrm{Greedy}(G,\mathrm{Extend}(G,F)).
\]
The extracted answer is therefore a program context with a single open
operation, \texttt{NEW-MST-EXTEND}.  That operation is where the later
refinements plug in:
\begin{lstlisting}
(ANSWER-IF (NEW-MST-COMPLETE G FOREST)
  (VALUES FOREST)
  (VALUES (NEW-MST-GREEDY G (NEW-MST-EXTEND G FOREST))))
\end{lstlisting}
This is the key abstraction boundary.  The proof term has committed to an
iterative greedy construction, but not to the policy used to find the next safe
extension.

\subsection{Safe Extensions and the Cut Property}

The next layer splits extension into two cases: add one safe edge, or add a
safe batch.  This is the point at which Kruskal and Prim/Jarnik can share one
single-edge interface while Boruvka can use a batch interface:
\begin{lstlisting}
(ANSWER-IF (NEW-SAFE-EDGE G FOREST EDGE)
  (ANSWER-IF (NEW-SAFE-BATCH G FOREST BATCH)
    (VALUES (NEW-MST-ADD-BATCH BATCH FOREST))
    (VALUES (NEW-MST-ADD-EDGE EDGE FOREST)))
  (VALUES (NEW-MST-ADD-BATCH BATCH FOREST)))
\end{lstlisting}
The cut-property refinement then justifies a safe single-edge extension:
\[
  \mathrm{CutRespected}(G,F,C)\land
  \mathrm{Crosses}(e,C)\land
  \mathrm{LightestCrossing}(G,e,C)
  \Rightarrow F+e.
\]
SNARK extracts:
\begin{lstlisting}
(VALUES (NEW-MST-ADD-EDGE EDGE FOREST))
\end{lstlisting}
This is the logical hinge: once an algorithm can be shown to choose an edge or
batch satisfying the relevant cut/safety predicate, it inherits the same
extension shape.

\subsection{Algorithm Families as Refinements}

The named algorithms enter only after the shared proof obligations are in
place:
\begin{itemize}
\item Kruskal refines extension by choosing a lightest edge that connects two
different forest components.
\item Jarnik--Prim refines extension by choosing a lightest edge on the
frontier of one growing component.
\item Boruvka refines extension by choosing a batch of lightest outgoing edges,
one per current component.
\end{itemize}
The extracted answers make their common structure explicit:
\begin{lstlisting}
(KRUSKAL-REFINEMENT
  (VALUES (NEW-MST-ADD-EDGE EDGE FOREST)))
(PRIM-REFINEMENT
  (VALUES (NEW-MST-ADD-EDGE EDGE FOREST)))
(BORUVKA-REFINEMENT
  (VALUES (NEW-MST-ADD-BATCH BATCH FOREST)))
\end{lstlisting}
Kruskal and Prim/Jarnik differ in the predicate used to produce \texttt{EDGE};
Boruvka differs in producing \texttt{BATCH}.  The answer terms expose exactly
that difference and no more.

\subsection{Concrete Implementations}

The executable layer interprets the symbolic leaves over finite Lisp graphs.
Edges are records \((id,u,v,w)\), forests are maintained with a union-find
structure, and the three strategies share the same output contract:
\begin{lstlisting}
(new-run-mst graph :strategy :kruskal)
(new-run-mst graph :strategy :prim)
(new-run-mst graph :strategy :boruvka)
\end{lstlisting}
On the demo graph, all three implementations return spanning forests of total
weight \(9\).  Their edge orders differ because the concrete algorithms expose
different traversal and tie-breaking choices, but they instantiate the same
abstract refinement chain.

\section{Limitations}

These examples are deliberately small.  They are working SNARK demonstrations
of answer extraction for classical synthesis patterns, not full reconstructions
of Manna and Waldinger's deductive-tableau derivations.  In particular:
\begin{itemize}
\item the square-root examples use abstract arithmetic predicates rather than a
complete theory of real numbers;
\item the GCD and quotient/remainder examples similarly use abstract integer
comparison and subtraction predicates in the proof layer;
\item the new stable-merge, stable-partition, and IF-expression examples use
abstract list and IF-expression theories;
\item the MST development reifies reachability, cuts, candidate trees, and
weight comparison as first-order predicates over finite graph objects;
\item the unification examples isolate key branches rather than proving a
single global total-correctness theorem for all expression pairs;
\item induction and termination arguments are represented by recursive
skeleton symbols rather than synthesized from a full well-founded induction
proof.
\end{itemize}
These choices keep the examples runnable and inspectable inside the existing
SNARK example suite while preserving the core answer-extraction phenomenon.

\section{From Proof Answers to Executable Code}

The SNARK proof answers are executable-looking, but they are still symbolic
terms in an object language.  For example, the unification proof answer contains
\texttt{MW-OCCURS}, \texttt{MW-UNIFY}, \texttt{MW-SUBST-OF}, and
\texttt{MW-COMPOSE}.  The square-root proof answer contains \texttt{MW-LE},
\texttt{MW-SQUARE}, \texttt{MW-PLUS}, and \texttt{MW-SQRT}.  The GCD and
quotient/remainder answers contain \texttt{MW-GT}, \texttt{MW-LT},
\texttt{MW-MINUS}, \texttt{MW-GCD}, \texttt{MW-QR}, and pair projection
symbols.  The new examples similarly contain abstract list constructors,
IF-expression accessors, path-assumption predicates, and recursive
simplification calls.  The MST proof answers contain abstract spanning-tree,
safe-edge, cut, batch, and strategy predicates.  SNARK has proved that a
witness with this shape exists under the stated obligations; it has not, by
itself, supplied concrete Common Lisp definitions for those abstract symbols.

The distribution therefore includes explicit executable interpretations.  For
square root, the recursive skeleton becomes:
\begin{lstlisting}
(defun mw-run-sqrt-step (r eps z)
  (if (<= (* (+ z eps) (+ z eps)) r)
      (+ z eps)
      z))

(defun mw-run-sqrt (r eps)
  (if (< (max r 1) eps)
      0
      (let ((z (mw-run-sqrt r (* 2 eps))))
        (mw-run-sqrt-step r eps z))))
\end{lstlisting}
For unification, \texttt{mw-run-unify} implements the generated branches using
concrete predicates for variables, constants, applications, occurs-check
failure, substitution application, and substitution composition.  A successful
sample call is:
\begin{lstlisting}
(mw-run-unify
 '(mw-app (mw-const f) (mw-var x))
 '(mw-app (mw-const f) (mw-const a)))
\end{lstlisting}
which returns a successful substitution binding \texttt{x} to
\texttt{(mw-const a)}.

For the arithmetic examples, the runners instantiate the symbolic comparisons
and recursive calls over Common Lisp integers:
\begin{lstlisting}
(defun mw-run-gcd (a b)
  (cond
   ((= a b) a)
   ((> a b) (mw-run-gcd (- a b) b))
   (t (mw-run-gcd a (- b a)))))

(defun mw-run-quotient-remainder (n d)
  (if (< n d)
      (list :quotient 0 :remainder n)
      (let ((qr (mw-run-quotient-remainder (- n d) d)))
        (list :quotient (1+ (getf qr :quotient))
              :remainder (getf qr :remainder)))))
\end{lstlisting}
The following command runs all executable demonstrations:
\begin{lstlisting}
(mw-executable-synthesis-demos)
(new-executable-synthesis-demos)
(new-run-mst-demo)
\end{lstlisting}
This split is deliberate: the proof answers document the synthesized control
structure; the \texttt{MW-RUN-*} and \texttt{NEW-RUN-*} layers supply the
host-language semantics needed to execute it.

\section{IF-Normalization Dialogue Example}

This appendix section records the IF-normalization exchange as a focused
example of how the synthesis suite evolved.  It includes the user prompt and
the public reasoning used to translate that prompt into the final SNARK
example.  It does not include private chain-of-thought.

\subsection{Prompt}

\begin{lstlisting}
The addition simplification and shortest-path relaxation are kind of lame. Remove those and instead, do the following example (taken from Boyer/Moore, A Computational Logic):

IF-expressions can be defined by a datatype that has a constructor for IF-expressions with three accessors: condition, thenBranch, and elseBranch, and the truth values: True and False, and variables. An IF-expression is in normal form if the condition part of any IF-expression is always a variable, and there are no redundant IF-expressions of the form IF(x, A, A). Write a simplifier for normal-form IF-expressions so that no variable is repeated along any branch.
\end{lstlisting}

\subsection{Public Reasoning}

The design correction was to remove the two weaker examples rather than keep
them as clutter.  The IF-normalization problem is a better stress test for
answer extraction because it combines recursive descent, branch-local
assumptions, equality of recursively simplified branches, and a normalization
invariant.

The SNARK object language used these symbols:
\begin{lstlisting}
NEW-IF, NEW-CONDITION, NEW-THEN-BRANCH, NEW-ELSE-BRANCH
NEW-ASSUMED-TRUE, NEW-ASSUMED-FALSE
NEW-EXTEND-TRUE, NEW-EXTEND-FALSE
NEW-SIMPLIFY-IF
NEW-SAME
\end{lstlisting}
The predicate \texttt{NEW-SAME} is the branch equality test used to collapse
\(\mathsf{IF}(x,A,A)\) after recursive simplification.

The first natural encoding treated the whole datatype at once: truth constants,
variables, and IF nodes.  That was too broad for this compact example harness,
so the SNARK proof obligation was narrowed to the recursive IF-node case while
the executable interpretation retained the complete leaf semantics.  This keeps
the extracted answer focused on the interesting synthesis step:
\begin{enumerate}
\item if the condition is already assumed true, simplify only the then-branch;
\item if the condition is already assumed false, simplify only the else-branch;
\item otherwise simplify both branches under extended assumptions;
\item if those simplified branches are equal, return one branch;
\item otherwise rebuild the IF node from the simplified branches.
\end{enumerate}

One additional consistency fact was added:
\begin{lstlisting}
(assert '(not (and (new-assumed-true (new-condition expr) env)
                   (new-assumed-false (new-condition expr) env)))
        :name 'new-if-assumptions-consistent)
\end{lstlisting}
This prevents the extracted answer from containing an impossible case where a
condition is simultaneously known true and false.

The executable demonstration then checks the host-language side of the gap.  A
normal-form expression with repeated tests of \(x\) along branches is simplified
to:
\begin{lstlisting}
(NEW-IF (NEW-VAR Y) NEW-TRUE NEW-FALSE)
\end{lstlisting}
which has no repeated variable along either branch and no redundant
\(\mathsf{IF}(x,A,A)\) subexpression.
